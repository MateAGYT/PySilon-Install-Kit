# Contributing to PySilon Installer

Thanks for your interest in contributing to PySilon Installer! This document provides guidelines for contributing to the project.

## Before You Start

1. **Read the Code of Conduct**: Make sure you've read and understood the project's [Code of Conduct](CODE_OF_CONDUCT.md).

2. **Check Existing Issues**: Before creating a new issue or pull request, check if something similar already exists.

3. **Fork the Repository**: If you're not a direct collaborator, fork the repository to your personal account.

## How to Contribute

### Reporting Bugs

If you find a bug, please:

1. Verify that the bug hasn't already been reported in the issues.
2. Create a new issue with:
   - A clear and descriptive title
   - Steps to reproduce the bug
   - Expected behavior
   - Actual behavior
   - Screenshots if applicable
   - System information (Windows 10/11, script version, etc.)

### Suggesting Enhancements

If you have ideas to improve the project:

1. Create an issue with the `enhancement` label
2. Clearly describe the proposed improvement
3. Explain why it would be useful
4. Provide examples of how it could be implemented if possible

### Submitting Pull Requests

1. **Create a New Branch**: Don't commit directly to the `main` branch.
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. **Make Your Changes**: Ensure your code follows the project's conventions.

3. **Test Your Changes**: Make sure the scripts work correctly before submitting the PR.

4. **Update Documentation**: If your changes affect functionality, update the README.md and any other relevant documentation.

5. **Submit the Pull Request**:
   - Go to the "Pull requests" tab of the original repository
   - Click on "New pull request"
   - Select your branch and submit the PR

## Code Style

### For Batch Scripts

- Use clear and descriptive comments
- Follow the existing header format in the files
- Use descriptive variable names
- Include error handling where possible
- Maintain consistency with existing code

### For Documentation

- Use consistent Markdown formatting
- Include examples when possible
- Keep instructions clear and concise
- Update the table of contents if necessary

## Review Process

1. All pull requests will be reviewed by the project maintainers
2. You may be contacted to make additional changes
3. Once approved, your contribution will be merged to the main branch
4. You'll be credited in the authors file if applicable

## Questions

If you have questions about contributing, don't hesitate to:

- Open an issue with the `question` label
- Contact the maintainers through the channels specified in the README
